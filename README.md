# MedCard — Електронна медична картка

> MedCard — навчальний MVP вебзастосунку для зберігання та перегляду особистої медичної інформації, керування історією відвідувань лікарів і захищеного доступу до даних.

## Про проєкт

**MedCard** — вебзастосунок, призначений для цифрового ведення особистої медичної картки.

Система дозволяє користувачам реєструватися, авторизуватися та працювати з історією медичних візитів.

### Основні можливості MVP

- Реєстрація та авторизація користувачів.
- Захищений доступ до особистого кабінету.
- Перегляд інформації про поточного користувача.
- Додавання візитів до лікарів.
- Перегляд історії медичних візитів.
- Видалення записів про візити.
- Збереження інформації в PostgreSQL.
- Взаємодія Frontend і Backend через REST API.

## Інструкція з локального розгортання (Deployment Instructions)

### 1. Системні вимоги

Для локального запуску необхідно встановити:

- Node.js 18 або новішої сумісної версії.
- npm.
- PostgreSQL.
- Git.
- Редактор коду, наприклад Visual Studio Code.

### 2. Клонування репозиторію

```bash
git clone https://github.com/biba02/medical-card.git
cd medical-card
git switch release/v1.0.0
```

### 3. Налаштування Backend

Перейдіть у папку Backend:

```bash
cd backend
npm install
```

Створіть файл `.env` на основі `.env.example`.

Приклад налаштувань:

```env
DATABASE_URL="postgresql://postgres:YOUR_PASSWORD@localhost:5432/medcard?schema=public"
JWT_SECRET="replace-with-your-own-long-random-secret"
JWT_EXPIRES_IN="1h"
PORT=5000
FRONTEND_URL="http://localhost:3000"
```

Параметри:

- `DATABASE_URL` — адреса підключення до PostgreSQL.
- `JWT_SECRET` — секретний ключ підписування JWT.
- `JWT_EXPIRES_IN` — термін дії токена.
- `PORT` — порт Backend.
- `FRONTEND_URL` — дозволена адреса Frontend для CORS.

**Увага:** реальні паролі та секретні ключі не можна публікувати в GitHub. Файл `.env` повинен залишатися поза системою контролю версій.

### 4. Підготовка бази даних

Створіть порожню базу даних PostgreSQL з назвою `medcard`.

Після налаштування `DATABASE_URL` виконайте:

```bash
npx prisma generate
npx prisma migrate deploy
```

Ці команди генерують Prisma Client та застосовують наявні міграції бази даних.

### 5. Запуск Backend

```bash
npm run dev
```

Для запуску у звичайному режимі:

```bash
npm start
```

Backend працює за адресою:

`http://localhost:5000`

### 6. Налаштування та запуск Frontend

Відкрийте другий термінал і перейдіть до папки Frontend:

```bash
cd frontend
npm install
```

Створіть файл `.env` на основі `.env.example`:

```env
VITE_API_URL=http://localhost:5000/api/v1
```

Запустіть Frontend:

```bash
npm run dev
```

Відкрийте адресу, яку покаже Vite. За умови використання порту 3000:

`http://localhost:3000`

Якщо Frontend запускається на іншому порту, необхідно відповідно налаштувати `FRONTEND_URL` у Backend.

### 7. Перевірка запуску

Після запуску обох частин системи необхідно:

1. Відкрити сторінку MedCard.
2. Зареєструвати нового користувача.
3. Авторизуватися.
4. Перейти до особистого кабінету.
5. Відкрити медичну картку.
6. Додати тестовий візит до лікаря.
7. Оновити сторінку та переконатися, що запис збережено.
8. Вийти з облікового запису.

## Посібник користувача (User Guide)

### 1. Реєстрація

1. Відкрийте MedCard.
2. Натисніть «Зареєструватися».
3. Введіть коректну електронну адресу.
4. Вкажіть пароль.
5. Натисніть «Створити акаунт».

Після успішної реєстрації користувач отримує доступ до особистого кабінету.

### 2. Авторизація

1. Перейдіть на сторінку входу.
2. Введіть електронну адресу та пароль.
3. Натисніть «Увійти».

Після успішної авторизації відкривається головна сторінка користувача.

### 3. Особистий кабінет

На головній сторінці можна переглянути:

- Електронну адресу поточного користувача.
- Ідентифікатор облікового запису.
- Роль користувача.
- Стан авторизації та підключення API.

### 4. Медична картка

Для роботи з історією відвідувань:

1. Відкрийте розділ «Медична картка».
2. Знайдіть форму «Додати новий візит».
3. Вкажіть дату відвідування.
4. Введіть ПІБ лікаря.
5. Зазначте спеціалізацію лікаря.
6. Вкажіть діагноз та рекомендації.
7. Натисніть «Додати візит».

Після успішного збереження новий запис з'явиться в розділі «Мої візити».

### 5. Перегляд і видалення візитів

У розділі «Мої візити» відображаються збережені медичні записи.

Для оновлення списку використовується кнопка «Оновити».

Для видалення запису використовується кнопка «Видалити візит».

### 6. Вихід із системи

Натисніть «Вийти» у верхній частині інтерфейсу.

Після завершення сеансу для повторного доступу до особистого кабінету потрібно авторизуватися знову.

## Тестування

Для перевірки працездатності застосунку використовуються ручні функціональні перевірки та засоби тестування Backend.

Основні сценарії перевірки:

- Відкриття головної сторінки.
- Реєстрація користувача.
- Авторизація.
- Перевірка захищеного API.
- Створення медичного візиту.
- Перевірка збереження запису після оновлення сторінки.
- Вихід із системи.

Для запуску тестів через Vitest можна використовувати:

```bash
cd backend
npx vitest run
```
